# Why Google can't find "tekivex" / "tekivex-ui" — diagnostic + action plan

This document walks through every cause that could be keeping the brand and library out of Google's index, and exactly what to do for each one.

## Quick triage

Run these four queries in an incognito window:

| Query | What a healthy result looks like |
|---|---|
| `site:ui.tekivex.com` | At least 1–5 pages indexed. **Currently: probably 0** because the site is a hash-routed SPA. |
| `site:npmjs.com tekivex-ui` | The npm package page should appear within 24–48h of publishing. |
| `tekivex-ui` (no operator) | Top result should be the npm page, then GitHub. **Currently: likely sparse or no results.** |
| `"tekivex"` (quoted) | Should surface npm, GitHub, anything that mentions the name. |

If `site:ui.tekivex.com` returns **0**, that's the smoking gun.

## Root causes, ranked

### 1. The current docs site is a hash-routed SPA — Google can't index hash fragments

`https://ui.tekivex.com/#/components/button` looks like the same URL as `https://ui.tekivex.com/#/components/modal` to Google. Search engines do **not** treat the `#` fragment as a separate document. So your entire site is **one URL** in Google's eyes, not 84.

**Severity:** This is THE biggest cause. Everything else is secondary until this is fixed.

**Fix:** The `docs-site/` Astro Starlight scaffold (committed in `e73fddd`) produces real flat URLs (`/components/button/`, `/components/modal/`, etc.). Each page SSGs to static HTML with a real `<title>` and `<h1>` on first byte.

**Action required (you):**

1. In Render dashboard, create a new Static Site service (or repoint the existing `ui.tekivex.com` service):
   - **Root directory:** `docs-site`
   - **Build command:** `npm install && npm run build`
   - **Publish directory:** `docs-site/dist`
2. Wait for the first deploy
3. The legacy `demo/` SPA can move to `playground.tekivex.com` (different subdomain) so it stays available without competing with the canonical docs

Time-to-Google-indexing once flipped: **48 hours – 2 weeks** for the first crawl, then steady incremental indexing.

### 2. No verified property in Google Search Console

Even with flat URLs, Google takes weeks to find a new domain on its own. Search Console is the official "hi please crawl this" channel.

**Action required (you):**

1. Go to [search.google.com/search-console](https://search.google.com/search-console)
2. Add property → **Domain** (covers all subdomains) → enter `tekivex.com`
3. Verify via DNS TXT record (your registrar's DNS panel)
4. Once verified, submit the sitemap: `https://ui.tekivex.com/sitemap-index.xml` (auto-generated by Astro Starlight)
5. Use the **URL Inspection** tool → enter `https://ui.tekivex.com/` → "Request Indexing"

### 3. No backlinks pointing at the canonical name

Google ranks domains partly by **inbound links from authoritative sites**. A brand-new project with zero backlinks is invisible until other sites link to it.

**Action required (you):** plant five high-authority backlinks in the next two weeks:

| Source | Effort | Link target |
|---|---|---|
| `awesome-react-components` GitHub repo (PR) | 30 min | `tekivex-ui` listing |
| `bestofjs.org` submit form | 10 min | Project entry |
| `js.coach` submit | 5 min | Search-engine-friendly listing |
| dev.to article: "Building tekivex-ui" | 1 hour | `https://ui.tekivex.com/` |
| HackerNews "Show HN" post | 30 min | Same |

Each gets crawled within days and feeds `tekivex-ui` into Google's index.

### 4. The brand "tekivex" has no Wikipedia entry / Wikidata QID

When Google sees a new term, it checks its knowledge graph. No entity match → low confidence in surfacing the result.

**Action required (you):** **don't try to create a Wikipedia page** — they get deleted for non-notable software. Instead:

- Get one good profile on **Crunchbase** (free, indexable)
- Build a strong **GitHub Org page** (`github.com/007krcs` is fine; an org page would be better for branding)
- Make sure the **npm package readme** mentions "TekiVex UI" and "tekivex-ui" in the first paragraph (already does)

Over 6–12 months Google builds a knowledge-graph entity from these signals.

### 5. "Did you mean..." auto-suggest is competing

Google's autocomplete may suggest "techvex" / "ttkvex" / similar misspellings before "tekivex" because the brand has low search volume. This **fixes itself** once direct searches for "tekivex" rise above some threshold (Google's internal — probably 50–100 searches/day from distinct users).

**Action required (you):** kickstart organic search volume:

- Tweet about tekivex-ui with the brand name + link from an account with ≥100 followers
- Get one comment on r/reactjs / r/webdev / HN that mentions "tekivex" by name
- Shipping the launch posts you already have drafted in `roadmap/05-launch-content.md`

Within 2–4 weeks of doing this, search auto-complete starts surfacing "tekivex" as a primary suggestion.

### 6. The package on npm is fine — but the npm SEO blob is thin

Search `site:npmjs.com tekivex-ui` and you'll see the npm page. Good. But the README on that page is what Google sees as the "first impression." Make sure:

- README has `# tekivex-ui` as the H1 (it does)
- First paragraph mentions accessibility, security, components — keywords that match real searches (it does)
- Includes install command (it does)
- **Add screenshots** — npm renders them; Google indexes the alt text

**Action required (you):** add 2–3 screenshots to the root `README.md` showing actual components rendered. A picture is the highest-density signal you can give Google about what this library *looks like*.

### 7. Google AI Overviews / SGE want structured content

Modern Google increasingly synthesises answers from **structured documents** (JSON-LD, FAQPage schema). The new docs-site already injects `SoftwareApplication` and `FAQPage` JSON-LD. The legacy demo site has it in `index.html` but only on the home route.

**Already done.** When you flip Render to docs-site, this lights up automatically.
